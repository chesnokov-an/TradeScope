## 3. Техническое задание

### 3.1. Введение

Разрабатываемая программа предназначена для анализа алгоритмических торговых стратегий на основе исторических данных о ценах финансовых инструментов.

Программа должна позволять исследовать результаты применения различных стратегий и наглядно представлять их эффективность с помощью графиков.

### 3.2. Назначение разработки

Цель разработки — снизить временные затраты на оценку эффективности алгоритмических торговых стратегий на основе исторических данных, используя числовые показатели и графическую визуализацию результатов.

### 3.3. Обязательные функциональные требования

Реализовать все следующие требования:

1. Программа должна обеспечивать загрузку исторических данных о ценах финансовых инструментов из CSV-файлов.
2. Программа должна поддерживать применение не менее трёх торговых стратегий к одному набору исторических данных.
3. Программа должна рассчитывать для каждой стратегии не менее трёх показателей эффективности:
   - итоговая доходность;
   - максимальная просадка;
   - количество совершённых сделок.
4. Программа должна отображать не менее двух типов графиков:
   - изменение цены финансового инструмента;
   - динамика капитала при использовании стратегии.
5. Программа должна обеспечивать сравнительное отображение результатов не менее трёх стратегий на одном наборе исторических данных.

Дополнительно реализовать:
- коэффициент Шарпа;
- количество прибыльных и убыточных сделок;
- процент прибыльных сделок;
- среднюю доходность сделки;
- итоговый капитал;
- сравнение стратегий по отдельным метрикам.

Необходимо обеспечить единообразие расчётов для всех стратегий.

## 4. Торговые стратегии

Реализовать ровно три основные стратегии. Они должны быть достаточно простыми для изучения и достаточно различными для проведения содержательного эксперимента.

Не использовать искусственно подобранные сигналы или заранее заготовленные результаты.

### 4.1. Стратегия пересечения скользящих средних (SMA Crossover)

Принцип работы:

Используются две простые скользящие средние:
- короткая SMA;
- длинная SMA.

Покупка осуществляется, когда короткая средняя пересекает длинную снизу вверх.

Продажа осуществляется, когда короткая средняя пересекает длинную сверху вниз.

Начальные параметры:
- короткий период: 20;
- длинный период: 50.

Параметры должны быть настраиваемыми.

Формула простой скользящей средней:

SMA(t) = (1 / N) * сумма Close(t-i), где i от 0 до N-1.

Необходимо корректно обрабатывать период прогрева индикатора.

### 4.2. Стратегия возврата к среднему на основе RSI (RSI Mean Reversion)

Использовать Relative Strength Index.

Начальные параметры:
- период RSI: 14;
- уровень перепроданности: 30;
- уровень перекупленности: 70.

Логика:
- покупка при пересечении RSI уровня перепроданности снизу вверх;
- закрытие позиции при пересечении RSI уровня перекупленности снизу вверх.

Допускается более простая и последовательная интерпретация сигналов, но выбранная логика должна быть подробно описана в методике исследования и одинаково реализована в программе и отчёте.

Использовать стандартный расчёт RSI на основе сглаженных средних приростов и снижений (метод Уайлдера).

### 4.3. Стратегия MACD

Использовать Moving Average Convergence Divergence.

Начальные параметры:
- быстрая EMA: 12;
- медленная EMA: 26;
- сигнальная EMA: 9.

Логика:
- покупка при пересечении линии MACD сигнальной линии снизу вверх;
- закрытие позиции при пересечении сверху вниз.

Формулы:

MACD = EMA(12) - EMA(26)

Signal = EMA(9, MACD)

Все параметры должны быть настраиваемыми.

### 4.4. Общие правила стратегий

Для всех трёх стратегий использовать единые правила:
- начальный капитал: 10 000 условных денежных единиц;
- торговля без кредитного плеча;
- только длинные позиции (long-only);
- одна открытая позиция одновременно;
- использование всего доступного капитала при открытии позиции;
- отсутствие одновременного открытия нескольких позиций;
- возможность настройки комиссии;
- возможность настройки проскальзывания;
- отсутствие использования будущих данных.

Сигнал, полученный на закрытии свечи t, должен исполняться не раньше следующей свечи, например по цене открытия свечи t+1.

Не допускать look-ahead bias.

Не допускать использования цены закрытия текущей свечи для исполнения сделки, если сигнал формируется на этой же цене закрытия.

Все стратегии должны проходить через один и тот же механизм бэктестинга.

### 5.2. Источники данных

Подготовить демонстрационный CSV-файл с историческими котировками.

Предпочтительно использовать реальные исторические данные из общедоступного источника с возможностью проверки происхождения.

В документации указать:

Если используются реальные данные, сохранить информацию об источнике и условиях их получения.

### 5.3. Исполнение сделок

Реализовать:
- открытие позиции;
- закрытие позиции;
- расчёт количества приобретаемого актива;
- комиссию при открытии;
- комиссию при закрытии;
- проскальзывание;
- учёт свободных денежных средств;
- учёт стоимости открытой позиции.

Предусмотреть корректную обработку последней незакрытой позиции.

Выбранное правило принудительного закрытия позиции в конце тестирования должно быть документировано.

### 5.4. Кривая капитала

Формировать временной ряд капитала для каждой стратегии.

Капитал должен включать:
- свободные денежные средства;
- текущую рыночную стоимость открытой позиции.

Необходимо учитывать нереализованную прибыль и убыток.

Все стратегии должны использовать одинаковые исходные данные, начальный капитал, комиссию и правила исполнения.

### 5.5. Показатели эффективности

Реализовать следующие показатели.

**Итоговая доходность:**

Return = (FinalEquity / InitialCapital - 1) * 100%

**Максимальная просадка:**

Drawdown(t) = (PeakEquity(t) - Equity(t)) / PeakEquity(t)

MaxDrawdown = max(Drawdown(t)) * 100%

**Количество сделок:**

Число завершённых торговых операций.

**Процент прибыльных сделок:**

WinRate = WinningTrades / TotalTrades * 100%

**Коэффициент Шарпа:**

Использовать периодические доходности капитала.

Sharpe = mean(returns) / std(returns) * sqrt(periodsPerYear)

Для дневных данных можно использовать 252 торговых дня.

Если стандартное отклонение равно нулю, корректно обрабатывать этот случай.

В отчёте обязательно указать используемую методику расчёта.

Не путать количество сделок, количество покупок и количество торговых циклов.

Все метрики должны рассчитываться централизованно, а не отдельно в каждой стратегии.

## 13. Технико-экономические показатели

В исходном ТЗ предусмотрены следующие показатели:

1. Сокращение трудозатрат: программа позволяет оценивать и сравнивать не менее трёх стратегий без ручного расчёта показателей.
2. Сокращение времени сравнения: целевое сокращение времени сравнительного анализа не менее чем на 50% относительно ручного расчёта.
3. Достоверность результатов: ошибки расчёта показателей допускаются не более чем в 3% случаев.

Необходимо сохранить эти требования в документации, но правильно обосновать их.

Для проверки точности использовать тестовые наборы с заранее известными результатами.

Для проверки порога 3% определить понятную методику проверки и критерий ошибки.

Различать точность вычислений, корректность алгоритма и достоверность рыночных предположений.

## 15. Качество кода

Применять следующие правила:

4. Не использовать panic для обычных ошибок.
5. Не игнорировать ошибки.

## 18. Критически важные принципы

В процессе всей работы руководствуйся следующими принципами:

**Первое. Корректность важнее красоты.**

Лучше простой график с математически верными данными, чем впечатляющая визуализация с некорректными вычислениями.

**Второе. Простота важнее избыточной архитектуры.**

Это учебный проект на Go. Код должен быть понятен начинающему разработчику, который самостоятельно сможет объяснить каждую функцию преподавателю.

**Третье. Отчёт должен соответствовать программе.**

Нельзя описывать функции, алгоритмы и эксперименты, которых нет в реализации.

**Четвёртое. Никаких выдуманных результатов.**

Все экспериментальные числа должны быть получены из реальных запусков.

**Пятое. Не имитируй выполнение работы.**

Файлы должны быть созданы, программа должна быть собрана, тесты должны быть запущены, PDF должен быть скомпилирован.

**Шестое. Не усложняй проект без необходимости.**

Не добавляй технологии, зависимости и функции, которые не улучшают решение поставленной задачи.

**Седьмое. Самостоятельно принимай разумные технические решения.**

Не останавливайся из-за незначительных неоднозначностей. Если решение можно принять на основании ТЗ и здравого смысла, принимай его, фиксируй в документации и продолжай работу.

Если возникает действительно блокирующее ограничение — например, отсутствие доступа к источнику исторических данных или невозможность использовать Typst, — не выдумывай результат. Найди допустимое решение, а ограничение явно зафиксируй.

**Главная задача: получить законченный, работающий, математически корректный и хорошо документированный учебный проект TradeScope, который студент сможет самостоятельно запустить, изучить, объяснить и защитить на курсовой работе.**

Начинай с аудита существующего репозитория и последовательно выполни все этапы до финальной проверки.
